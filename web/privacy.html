Skill Swipe Privacy Policy

Effective November 20, 2026 (renamed from RepoSwipe; safety scan, Super Like forks, star-swipe actions, MCP tiles and GitHub import added) · Applies to the Skill Swipe iOS app, the web app at swipe.yeete.ai and the Skill Swipe browser extension · Terms of Use

Skill Swipe (formerly RepoSwipe) is built to be private by design. An account is optional. There is no advertising and no analytics or tracking of any kind.

What stays on your device

Everything you do in Skill Swipe — the repos you swipe, your Stack, achievements, pack progress, channel settings and language — is stored only on your device (in the app's local storage). We can't see it. Deleting the app deletes it. You can export it yourself at any time from the Stack screen and restore it from that backup.

Browser storage (the web app)

The web version at swipe.yeete.ai keeps a small number of items in your browser's own localStorage. It does not set any tracking cookies. The items are:

  • reposwipe.v2 — your Stack, swipe history, groups, pack progress, achievements, channel settings, filters and language choice.
  • reposwipe.auth — if you signed in, the Supabase session token that keeps you signed in on this browser. Signing out clears it. It is never shared with other sites.
  • reposwipe.scan — the safety-scan verdicts cached from your own browsing, so flipped cards don't re-check the same files. It holds up to 400 entries for up to 7 days.

These stay on this browser, survive refreshes, and are removed when you clear site data for swipe.yeete.ai. We cannot read them.

Optional account

You can use Skill Swipe without an account; everything then stays on your device as described above. If you choose to sign in with GitHub or Google, we store the account's email address, display name, avatar and the sign-in provider's user id, plus a copy of your Stack, groups, achievements, pack progress and settings so they sync across your devices. This is held by our authentication and database provider, Supabase, with per-user access rules — only you can read your row. Your AI keys, MCP server tokens and GitHub personal access token are never synced. A GitHub sign-in also lets the app read public repositories using your GitHub account's rate limit. It asks for nothing else unless you switch on automatic forks (below). Signing out keeps your data on the device; to delete your account data entirely, email the address below and we'll remove the row.

What leaves your device, and where it goes

  • GitHub's public API (api.github.com) — to fetch public repository data (names, descriptions, stars, READMEs). These requests carry no information about you beyond what any web request includes (your IP address, handled under GitHub's privacy statement).
  • Optional GitHub token. If you choose to paste a personal access token to raise GitHub's rate limit, it is stored only on your device and sent only to api.github.com. It is never sent to us or to anyone else, and it is deliberately excluded from backups you export.
  • Optional AI keys and MCP servers. If you choose to connect your own Claude, ChatGPT or Perplexity API key, or add an MCP server, those keys and server addresses are stored only on your device and sent only to the provider or server you entered (api.anthropic.com, api.openai.com, api.perplexity.ai, or your MCP server's URL). Your questions and the repository details you ask about go to that provider under its own privacy policy. Nothing is sent to us, and keys are excluded from backups you export.
  • Safety scan. Before a repository is forked or sent to an AI — and when you flip a card or add a repo — the app reads that repository's public file list and a handful of its public files (install hooks, setup scripts, skill and agent instruction files, tool configs) straight from GitHub (api.github.com and raw.githubusercontent.com) and checks them on your device against a fixed list of warning signs. Nothing about you or your Stack is sent anywhere; the result is kept on your device. The scan is an automated check of a sample of files. It can miss things and it can be wrong — it is a help, not a guarantee that a repository is safe.
  • Super Like: fork and send (off until you turn it on). If you switch on "Fork to my GitHub", Skill Swipe asks GitHub for one extra permission — public_repo, which lets it create forks of public repositories in your account. GitHub shows you that request on its own screen. The resulting token stays on your device, is sent only to api.github.com, and is never synced or backed up; the app uses it only to create the fork you asked for. GitHub's permission is broader than that single action (it also allows writing to your public repositories), so you can leave it off and use GitHub's own fork page instead, and you can revoke it any time at github.com → Settings → Applications. If you switch on "Send to my main AI", a Super Like opens the AI you chose (Claude, ChatGPT, Perplexity or Grok) with the repository link, your fork's link and the safety-scan summary in the prompt; from there that provider's privacy policy applies.
  • Import from GitHub. If you tap "Import from my GitHub", the app reads your public starred repositories and your own public repositories from api.github.com with your GitHub token and adds them to your Stack. Private repositories are never imported.
  • Auto-translate. When a repository's description or README is written in a language other than the one you use Skill Swipe in, that repository text is sent to a translator so you can read it. If you have connected your own AI key, your AI does the translation; otherwise the text goes to Google Translate (translate.googleapis.com) under Google's privacy policy. Only the repository's public text is sent — never your Stack, settings or keys. You can turn this off in the You tab.
  • Optional share links. If you tap "Share link", the list of public repositories in your Stack is uploaded to our share service so the link can display it. The link contains repository names and metadata only — nothing that identifies you. A random, anonymous device identifier is used so you can update your own link; it isn't tied to any personal information.
  • Opening links. Tapping "Open on GitHub", "Fork", or any of the "Send to AI" options opens that third-party site (GitHub, Claude, ChatGPT, Perplexity or Grok) in a browser sheet. From that point, their privacy policies apply. The repository link is included in what you open; nothing else about you is passed along.
  • The feed itself. The repositories you see are gathered once an hour by automated "scouts" that query GitHub's public search from the project's own GitHub account and publish the results as static files on swipe.yeete.ai. Loading them tells us nothing about you. Repositories the scouts' safety scan considers dangerous, and groups of look-alike repositories that match a fake-star pattern, are left out of the feed.
  • Browser extension. The Skill Swipe extension adds a button to github.com repository pages. It reads only the repository name from the page you are on, and only when you click the button, to open that repo in Skill Swipe. It collects nothing, stores nothing, and makes no network requests of its own.

What we never do

  • No analytics, crash reporters, advertising SDKs, or third-party trackers.
  • No collection of your name, email, contacts, location, photos, or device identifiers — unless you sign in, in which case only the account details listed above.
  • No selling or sharing of data — there is none to sell.

Takedown and removal requests

Skill Swipe shows public repositories that live on GitHub. If you are the owner of a repository and would rather it didn't appear in Skill Swipe, email takedown@yeete.ai with the repository URL (for example github.com/your-name/your-repo) and a one-line note that you own it. We'll remove it from the live feed, the starter packs, This Week's Drop, cached scout snapshots and share pages within seven days. DMCA takedown notices go to the same address and are handled the same way. If you later want it listed again, write to the same address.

Children

Skill Swipe is rated 4+ and collects no personal information from anyone, including children. To create an account you must be at least 13 years old (16 if you live in the European Economic Area or the United Kingdom); see the Terms of Use.
